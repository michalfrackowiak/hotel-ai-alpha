# v0.3.0 — Guest self-service

Released **13 November 2026**.

## Summary

v0.3.0 lets a guest change or cancel a reservation without calling reception. It adds a configurable cancellation policy, a single fee preview shared by every channel, in-place reservation modification, an append-only audit trail, a staff operations dashboard and a month-grid rate calendar.

The release keeps the v0.2.0 invariants: one booking write path, per-room availability, post-commit calendar/email side effects and signed guest access.

## What's new

### Cancellation policy

- `apps/hotel/cancellation.py` is the single source of truth for fees.
- Pending holds are always free to release.
- Confirmed bookings are free until `check_in - CANCELLATION_FREE_DAYS` (default 3).
- Late cancellations charge the first `CANCELLATION_FEE_NIGHTS` stored nightly rates (default 1), capped at the booking total.
- `GET /api/v1/bookings/<REFERENCE>/cancellation-preview/` and the booking page show the same amount that `cancel_booking()` records.
- Cancellations store `cancellation_reason`, `cancellation_note`, `cancellation_fee` and `cancelled_by`.

New environment settings:

```text
CANCELLATION_FREE_DAYS=3
CANCELLATION_FEE_NIGHTS=1
```

### Reservation modification

- `PATCH /api/v1/bookings/<REFERENCE>/` changes dates, room type or occupancy.
- The signed booking page exposes the same form.
- Availability and price are re-checked in one transaction with `exclude_booking`, so the guest cannot block themselves.
- Only pending and confirmed bookings are modifiable; terminal states return `409 not_modifiable`.

### Audit log

- `BookingEvent` records create, confirm, modify, cancel and expiry transitions.
- Each row stores the actor (`guest`, `staff`, `agent`, `system`), channel, summary and JSON before/after data.
- The model rejects updates; the admin is read-only and has no add/delete actions.

### Operations dashboard

`/ops/` (staff only) shows:

- today's arrivals and departures;
- active and expired holds;
- failed calendar syncs;
- confirmed bookings with no confirmation-email marker;
- the most recent booking events.

### Rate calendar

- `DailyRate` stores a nightly rate and optional minimum stay per room type and date.
- A daily rate replaces the calculated rate for that night; pricing rules are skipped.
- `min_nights` is enforced by `quote()` and availability search omits room types that violate it.
- Reception edits a month grid at **Admin → Daily rates → Rate calendar**.

## Upgrade notes

1. Apply the migration:

   ```powershell
   .\.venv\Scripts\python.exe manage.py migrate
   ```

2. Optionally set `CANCELLATION_FREE_DAYS` and `CANCELLATION_FEE_NIGHTS`.
3. Refresh the Polish catalogue if you deploy from source:

   ```powershell
   .\.venv\Scripts\python.exe scripts/update_translations.py
   .\.venv\Scripts\python.exe scripts/compile_translations.py
   ```

The migration is additive: new booking fields default to empty/zero, and existing bookings remain readable.

## Known limits

- The cancellation policy is hotel-wide, not per rate plan.
- The rate calendar sets explicit nightly rates; derived rate plans and closed-to-arrival rules are planned for v0.4.0.
- The operations dashboard is read-only.
- The audit log is visible in the admin and on `/ops/`; there is no external log shipping yet.
