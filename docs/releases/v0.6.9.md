# v0.6.9 — the guided booking scenario, Polish first, SMS delivery

**Released:** 2026-11-15

## Summary

Rebuilds the chat and voice booking flow as the seven-step reception script: welcome and language choice, arrival date, departure date or duration, guest count, live availability and room selection, a confirmation prompt, and a final choice between an email or SMS confirmation. Polish is now the default language everywhere, with a dynamic switch to English, and the demo hotel is branded **Resort Neptun Jastrzębia Góra**.

## Changes

- **Seven-step conversation flow** (`apps/agents/defaults.py`, `apps/providers/demo.py`)
  - The system prompts and the offline demo policy now walk the guest through the scenario in order instead of asking for everything at once.
  - Step 1 greets in Polish and offers English; step 2 collects the arrival date; step 3 collects the departure date or a duration (`na 3 noce`, `for 3 nights`, `na tydzień`); step 4 collects the total guest count; step 5 calls `check_availability` and reads back the options; step 6 asks for confirmation; step 7 asks for email or SMS and collects the matching contact detail.
  - Ordinal dates, word numbers, Polish month names, relative dates and duration phrases are parsed deterministically — no extra language model and no new dependency.
- **Default Polish with dynamic switching** (`config/settings/base.py`, `apps/agents/engine.py`, models)
  - `LANGUAGE_CODE`, `HOTEL["default_language"]` and the `Conversation`/`Client`/`Booking` language defaults are now `pl`.
  - The engine detects an explicit request for English (or Polish) before each turn and flips the conversation language, so a guest can switch mid-conversation.
- **Confirmation SMS delivery** (`apps/hotel/sms_providers.py`, `apps/hotel/notifications.py`)
  - New pluggable provider layer: `console` (default, records to the log and `ConsoleSmsProvider.outbox`, works offline and in tests) and `twilio` (Posts to the Twilio Messages API when the credentials are set).
  - `send_booking_confirmation_sms()` renders a short, localised text from `templates/hotel/sms/booking_confirmation.txt`, stores the provider message id and keeps `confirmation_sms_sent_at` idempotent.
  - New booking fields: `confirmation_sms_sent_at`, `confirmation_sms_status`, `confirmation_sms_error`, `confirmation_sms_provider_id`, `confirmation_sms_attempts`, `confirmation_sms_last_attempt_at`.
  - SMS failures never roll back a reservation, matching the existing email behaviour.
- **New agent tools** (`apps/agents/tools.py`)
  - `send_confirmation_sms` sends or resends the confirmation text, optionally storing a phone number first.
  - `transfer_to_human` records a handover request (reason, channel, timestamp) in the conversation state for non-booking enquiries and explicit requests for a receptionist.
  - The booking payload now exposes `confirmation_email_status` and `confirmation_sms_status`.
- **Admin** (`apps/hotel/admin.py`)
  - Booking list and filters include the SMS status; a **Confirmation SMS** fieldset shows the delivery state, provider id and attempt history; a **Resend confirmation SMS** action resends explicitly.
- **API** (`apps/api/serializers.py`, `apps/api/views.py`)
  - Booking payloads expose `confirmation_sms_status` and `confirmation_sms_error`; the create/chat defaults are Polish.
- **Branding** — `Resort Neptun Jastrzębia Góra` replaces `Hotel Aurora` in settings, the manifest, the channel-feed user agent, the smoke test, the translation tooling and the README. The assistant is still called **Aurora**.
- **Translations** — 17 new user-facing strings added to `scripts/pl_translations.py` and compiled into the catalogue (617 strings extracted, all translated).
- **Tests** (`tests/test_agent_flow.py`)
  - Rewritten for the sequential scenario: arrival → departure → guests → offer → room selection → confirmation → email/SMS → closing, plus Polish booking, mid-conversation language switch and human handover.
  - `ConsoleSmsProvider.reset()` added to the autouse fixture; English-content web tests now request English explicitly because the default language is Polish.

## Migrations

- `agents.0003_alter_conversation_language` — conversation language default `pl`.
- `agents.0004_refresh_default_prompts` — refreshes only the previous default prompts/greetings so existing databases pick up the new scenario without overwriting customised text.
- `hotel.0014_booking_confirmation_sms_attempts_and_more` — the six SMS fields plus the `pl` language defaults on `Booking` and `Client`.

## Upgrade notes

- Run `manage.py migrate`. Existing conversations and bookings keep their stored language; only the model defaults changed.
- `agents.0004` updates rows that still hold the old default prompts. If you customised the prompts in the admin, they are left untouched.
- New optional environment variables: `BOOKING_SMS_ENABLED` (default `true`), `SMS_PROVIDER` (`console` or `twilio`), `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM_NUMBER`. The console provider is the offline default, so no credentials are required.
- New branding variables: `HOTEL_TAGLINE`, `HOTEL_DEFAULT_LANGUAGE`, `HOTEL_CONTACT_EMAIL`, `HOTEL_CONTACT_PHONE`, `HOTEL_ADDRESS`.
- No new Python dependencies.
