# v0.1.0 — Hotel Aurora AI reception alpha

Released **13 November 2026**. This is the first end-to-end alpha: a bilingual AI receptionist that takes real reservations by chat and voice, prices them from hotel data and mirrors confirmed bookings into one calendar per room.

## Highlights

- **Chat and voice concierge** for English and Polish at `/chat/` and `/voice/`.
- **Real booking lifecycle**: availability → VAT-inclusive quote → 30-minute hold → guest confirmation → confirmed reservation.
- **Provider-agnostic LLM layer**: OpenAI, Anthropic, Ollama/self-hosted and an offline deterministic demo policy. The alpha works with no API keys.
- **Per-room calendar sync** through a provider interface, with a fake adapter for demos and a Google Calendar adapter for real calendars.
- **Booking self-service**: lookup, confirm and cancel by reference at `/booking/`.
- **Operable admin**: rooms, room types, clients, pricing rules, bookings, AI providers, prompts, conversations and calendars.
- **Docker deployment** with SQLite on a named volume, WhiteNoise static files, gunicorn and a boot-time migrate/seed/superuser sequence.
- **Bilingual UI** with a language switcher and a committed Polish gettext catalogue.

## Upgrade and setup notes

- The demo database is created by `manage.py migrate` followed by `manage.py seed_demo`.
- The seeded local superuser is `admin` / `AuroraAdmin!2026`. **Change it** before any non-local exposure.
- With no provider key the default provider is `demo`. Set an OpenAI/Anthropic key and mark that provider as default to use a live model.
- The demo calendar connection uses the `fake` provider. Google Calendar requires credentials and one `RoomCalendar` per room.
- SQLite is the only supported database in this release.

## Known limitations

- No payment, deposit, invoice or channel-manager integration.
- Booking lookup is reference-only; there is no guest authentication.
- Throttling is in-memory per process.
- Calendar sync is one-way (hotel → calendar).
- Email/SMS confirmations are not sent.
- The demo policy is rule-based; use a real LLM for open-ended conversation.
- Single-container deployment; not sized for high concurrency or multi-tenancy.
