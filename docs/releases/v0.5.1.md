# v0.5.1 — Channel manager

Released **14 November 2026**.

## Summary

v0.5.1 is the first slice of the v0.6.0 milestone: a one-way channel manager
built on iCal. OTA reservations are imported into per-room `RoomBlock` rows, so
availability, creation and modification honour them without creating synthetic
bookings or touching the booking write path. The hotel's own availability is
exposed as a signed iCal feed an OTA can subscribe to. Conflicts with local
blocking bookings are counted and surfaced on `/ops/`.

## Imported reservations

- `ChannelFeed` is per physical room and stores `url`, `last_synced_at`,
  `last_error`, `last_event_count` and `conflict_count`.
- `RoomBlock` stores `room`, nullable `feed`, `check_in`, `check_out`, `source`
  (`channel` / `manual`), `external_uid` and `summary`.
- `sync_feed()` unfolds folded iCal lines and parses `DATE` and `DATE-TIME`
  values (Z and naive/TZID), skips `STATUS:CANCELLED`, upserts by
  `(feed, external_uid)`, removes stale events and preserves existing blocks on
  fetch failure.
- `sync_all_feeds()` and the `sync_channel_feeds` management command (with
  `--apply` for a dry-run default) drive the loop; the scheduler sidecar now
  runs `sync_channel_feeds --apply`.
- `booked_room_ids()` unions overlapping `RoomBlock` room ids, so search and
  quote see imported blocks. `Booking.clean()` rejects a booking that overlaps a
  block, and `create_booking()`/`modify_booking()` surface it as
  `no_availability` / `invalid_stay`.
- Reception can add manual blocks in the admin; the ops dashboard lists
  upcoming blocks.

## Export feed

- `build_room_calendar(room)` emits one `VEVENT` per blocking booking (pending
  holds as `TENTATIVE`, confirmed as `CONFIRMED`) plus one per `RoomBlock`.
- The feed is served at `/calendar/<token>.ics` using a signed token
  (`django.core.signing`, salt `hotel.channel_feed`); an invalid or expired
  token returns `404`.

## Operations

- `/ops/` shows channel feed error and conflict counts, a feed table (last
  synced, event count, conflicts, last error) and an upcoming room-block table.

## Upgrade notes

1. Run `manage.py migrate`. Migration `0011_channelfeed_roomblock` is
   required.
2. New optional environment variable: `CHANNEL_FEED_TIMEOUT_SECONDS` (10).
3. On a host without Docker, add `sync_channel_feeds --apply` to the same
   scheduler that runs `expire_holds` and `reconcile_calendars --apply`.
4. No API contract changes. The export feed lives at
   `/calendar/<token>.ics`.

## Known limits

- Import is one-way: OTA edits and cancellations are reflected on the next
  sync, but conflicts are counted, not auto-resolved.
- The export feed is a subscription URL, not a push; OTAs poll it.
- Multi-currency display and the PWA install prompt move to the next slice.
