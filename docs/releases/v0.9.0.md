# v0.9.0 - Payments and deposit tracking (manual/admin-first)

**Released:** 2026-11-20

## Summary

Bookings now track what a guest owes and has paid without introducing direct card/acquirer integration or automatic capture. Reception can review payment and deposit state in the admin and `/ops/`, guests see clear payment/deposit summaries on the signed booking page and in confirmations, and staff can record payment changes with an append-only audit trail via the admin, `manage.py record_payment`, or a staff-only API.

## Changes

- **Payment tracking foundation** (PR #7, `616ea2b`)
  - Added booking payment fields: `payment_status` (unpaid/partially paid/paid/refunded), `amount_paid`, `payment_method`, `payment_reference`, `paid_at`, `payment_notes` (migration `hotel.0017_booking_payment_tracking`).
  - Booking admin list/filter/fieldset for payment state; token-gated booking API responses expose payment tracking fields.
  - `/ops/` highlights active/pending bookings needing payment attention (unpaid or partially paid).

- **Guest-facing payment summaries** (PR #8, `bba8ccf`)
  - Added `Booking.amount_due` and exposed it in token-gated booking responses.
  - Guest booking detail page and confirmation email/SMS templates show payment summaries (status, amount paid, balance due) with Polish translations and tests.

- **Payment audit trail and staff recording path** (PR #9, `a9eebf0`)
  - Append-only `BookingEvent` payment types: `payment_recorded`, `payment_adjusted`, `payment_refunded`, `payment_waived` (migration `hotel.0018_bookingevent_payment_types`).
  - `apps.hotel.booking_service.record_booking_payment()` single write path for staff payment changes; `manage.py record_payment` command (actions `recorded`/`adjusted`/`refunded`/`waived`) with tests and Polish translations.

- **Hotel-level deposit/prepayment policy** (PR #10, `83567e6`)
  - Configurable hotel-level deposit policy via `settings.HOTEL` / env (`DEPOSIT_POLICY=none|percent|fixed`, `DEPOSIT_VALUE`).
  - `apps/hotel.deposit.deposit_summary()` single source of truth for deposit amount, amount due now, balance due and guest-facing policy text, surfaced via `Booking` helpers, booking API (`deposit_amount`, `amount_due_now`, `deposit`), guest booking detail, and confirmation email/SMS templates.

- **Payment/deposit documentation alignment** (PR #11, `10eeb55`)
  - Updated README/ARCHITECTURE/API/ROADMAP/PROJECT_MEMORY to reflect manual payment/deposit tracking, configurable deposit policy, and staff payment recording/audit.

- **Rate-plan deposit/prepayment policy overrides** (PR #12, `a0cf96d`)
  - Optional per-`RatePlan` deposit policy/value (inherit hotel policy, no deposit, percentage of total, or fixed amount) with migration `hotel.0019_rateplan_deposit_policy` and admin fields.
  - `deposit_summary()` resolves the effective policy from `booking.rate_plan` when overridden, falling back to hotel-level settings; guest-facing surfaces remain consistent (Booking/API/guest/confirmations) with tests and translations.

- **Staff-only payment-recording API** (PR #13, `05555d7`)
  - `POST /api/v1/bookings/<reference>/payments/` for authenticated Django staff users (DRF `IsAdminUser`, consistent with `/admin`/`/ops/`); **guest booking tokens do not grant access**.
  - Accepts `record_payment`-aligned fields (`action`, `amount`/`amount_paid`, `status`/`payment_status`, `method`/`payment_method`, `payment_reference`, `notes`/`payment_notes`, `paid_at`, `summary`), records via `record_booking_payment()` (append-only audit, `channel=api`), and returns the updated booking.
  - Tests and API documentation added.

## Migrations

- `hotel.0017_booking_payment_tracking` - adds booking payment tracking fields/status/method/reference/paid-at/notes.
- `hotel.0018_bookingevent_payment_types` - adds append-only payment event types for payment audit.
- `hotel.0019_rateplan_deposit_policy` - adds per-rate-plan deposit policy/value overrides.

## Out of scope

- Direct card/acquirer integration (Stripe/Adyen/etc.) and PCI-sensitive payment form handling.
- Automatic capture, chargeback handling, or accounting-system sync.

## Upgrade notes

- Apply migrations: `python manage.py migrate`.
- Optional hotel-level deposit configuration: `DEPOSIT_POLICY=none|percent|fixed`, `DEPOSIT_VALUE` in `.env` / settings. Rate plans can override the deposit policy in the admin (inherit/no deposit/percent/fixed).
- Staff payment recording options: Django admin, `manage.py record_payment`, or `POST /api/v1/bookings/<reference>/payments/` (requires an authenticated `is_staff` user; guest booking tokens are not accepted). All paths use `record_booking_payment()` and append immutable payment audit events.
- No existing booking, confirmation, cancellation, email, or SMS behavior is removed; payment handling remains manual/admin-first with no direct card processing or automatic capture.
