# v0.8.0 — SMS confirmation retry/backoff parity

**Released:** 2026-11-20

## Summary

Confirmation SMS delivery now follows the same operational model as email: failed or unsent confirmations are retried automatically with exponential backoff, the scheduler/management command process due retries, and reception can see SMS retry state in `/ops/` and the admin. Scheduler load coverage is extended to pending and due SMS retry backlogs.

## Changes

- **SMS retry/backoff parity** (PR #4)
  - Added `Booking.confirmation_sms_next_retry_at` and migration `hotel.0016_booking_sms_retry_fields` to track scheduled SMS retries.
  - Added SMS retry settings: `SMS_MAX_ATTEMPTS`, `SMS_RETRY_BASE_SECONDS`, `SMS_RETRY_MAX_SECONDS` (mirroring email backoff configuration).
  - `send_booking_confirmation_sms()` now records failed-attempt backoff (`confirmation_sms_next_retry_at`) and clears retry state on successful send, while keeping per-attempt `SmsDelivery` history and existing idempotent/after-commit behavior.
  - Added `send_pending_confirmation_sms()` and `send_booking_sms` management command (`--force` supported) to process due, unsent confirmation SMS retries under the attempt cap.
  - `docker/scheduler.sh` now runs `python manage.py send_booking_sms` alongside existing hold/calendar/email tasks.

- **Operations and admin visibility** (PR #4)
  - `/ops/` shows "SMS waiting to retry" and includes "Next retry" for problem SMS deliveries, in addition to existing SMS delivery history and inbound reply visibility.
  - Booking admin exposes SMS retry/attempt timing fields for operational inspection.

- **Scheduler load coverage** (PR #5, PR #6)
  - `tests/test_scheduler_load.py` covers a backlog of 100 pending unsent confirmation SMS messages.
  - `tests/test_scheduler_load.py` also covers a backlog of 100 due failed SMS retries, confirming retry-queue processing remains within budget.

- **Docs and translations** (PR #4)
  - Updated `README.md`, `docs/ARCHITECTURE.md`, `docs/PROJECT_MEMORY.md`, `docs/ROADMAP.md` and `.env.example` for SMS retry/backoff, scheduler/command usage, and ops/admin behavior.
  - Polish translations updated and compiled for new SMS retry/ops copy.

## Upgrade notes

- Apply migrations: `python manage.py migrate`.
- If running without Docker, add `python manage.py send_booking_sms` to the same schedule/cron as `send_booking_emails` so failed/unsent confirmation SMS messages retry automatically.
- Optional tuning/env vars: `SMS_MAX_ATTEMPTS`, `SMS_RETRY_BASE_SECONDS`, `SMS_RETRY_MAX_SECONDS` (defaults mirror email retry policy).
- SMS provider delivery receipts and inbound replies continue to use `POST /api/v1/sms/webhooks/<provider>/` and `SMS_WEBHOOK_SECRET` / `X-Sms-Webhook-Secret` when configured.
- No existing booking, email, or SMS webhook behavior is removed; failures still never roll back a reservation, and reception can resend confirmations manually from the admin when needed.
