# v0.6.10 — the demo agent remembers the guest count

**Released:** 2026-11-19

## Summary

Patch release for the offline demo provider. A guest who answered the guest-count question with a bare number ("2", "two", "dwa") was asked for the count again after availability, after room selection and after the confirmation prompt, and the booking could never complete. In Polish the same bare "2" also switched the conversation to English, because the greeting offers English on "2".

## Changes

- **Guest count survives later turns** (`apps/providers/demo.py`)
  - `_guest_count_from_history()` scans the whole message list for the "number of guests" question and the user reply that followed it, so a count given as a bare number or word is still known after the conversation moves on to availability, room selection and confirmation.
  - `_asked_guests()` and `_asked_check_out()` now skip empty assistant messages, which is what a tool-call turn leaves in the history.
- **Bare numbers only switch language at the start** (`apps/agents/engine.py`)
  - `detect_language()` takes `allow_number_switch`; the engine disables it once the conversation has a user message. A bare "2" is a guest count, room choice or confirmation mid-conversation, not a language request.
  - Explicit requests ("English, please.", "Po polsku, proszę.") still switch the language at any point.
- **Regression tests** (`tests/test_agent_flow.py`)
  - English and Polish flows that answer the guest question with "2", then select a room, confirm, choose email and finish the booking. The Polish test also asserts the conversation stays Polish.
  - A unit test for `detect_language` covering number switching before and after the first reply.
