# v0.11.0 - OpenLine phone voice integration (in progress)

**Status:** Unreleased (feature branch `feature/v0.11.0-openline-integration`)

## Summary

v0.11.0 adds the initial OpenLine phone-voice integration so real phone calls can be handled by the existing Hotel Aurora conversation engine and booking tools. The work is implemented behind feature flags and is not yet end-to-end validated against a real OpenLine server.

## Changes

- **OpenLine control plane**
  - Extended the vendored `django_openline` client/services with `attach_stream`, `detach_stream`, and `get_stream`.
  - Added webhook-driven phone handling: OpenLine webhook events map idempotently to domain `PhoneCall` records and phone `Conversation`s.
  - In `webhook_attach` mode, inbound ringing calls can attach the agent media stream through OpenLine `POST /v1/calls/{id}/stream`.

- **Phone domain model and admin**
  - Added `apps.voice.PhoneCall` with provider/external id, direction, status, timestamps, transcript, summary, and metadata.
  - Added read-only `PhoneCall` admin and `/ops/` phone metrics/recent call visibility.
  - Added `Conversation.Channel.PHONE` and phone-related `AgentSettings` fields (greetings, disclosure, transfer number, max duration, silence timeout, enable flag).

- **ASGI media bridge**
  - Added `WS /ws/voice/openline/` ASGI endpoint for Twilio-format OpenLine media streams.
  - Bridge requires per-call stream tokens (generated/persisted in `PhoneCall.metadata["stream_token"]`, passed via `customParameters.streamToken` or `?token=`); missing/invalid tokens are rejected.
  - Implemented µ-law/PCM audio conversion, basic RMS VAD, DTMF buffer handling, barge-in (`clear`) with active utterance-task cancellation, background utterance handling, delayed filler prompts, and turn latency logging.
  - Implemented phone session flow: STT -> `AgentEngine.handle_user_message()` -> TTS, with transcript persistence and simple end-of-call summary.

- **Safety and guardrails**
  - Phone disabled by default (`VOICE_PHONE_ENABLED=false`, `AgentSettings.phone_enabled=False`); attach and bridge admission gate on both.
  - Added max call duration, silence reprompt/timeout, concurrent-call cap, per-number hourly cap, and daily-minute cap checks.
  - `transfer_to_human` includes phone transfer metadata; bridge performs best-effort provider transfer and falls back to clean hangup when transfer is unavailable. Late terminal webhooks do not overwrite `TRANSFERRED`.
  - Added basic PII log redaction, caller opt-out phrase handling (`recording_opt_out` metadata + `[opt-out]` transcript markers), webhook payload sanitization with sensitive keys redacted regardless of length, and `prune_phone_data --days N [--apply]` for dry-run/default redaction of old terminal `PhoneCall` PII plus linked phone `Conversation`/`Message` PII. `VOICE_PHONE_RETENTION_DAYS` configures the default retention window (default 30); retention period and formal consent/legal review remain pending before pilot.
  - Outbound placement creates the phone `Conversation` only after successful OpenLine placement to avoid orphan conversations on provider failure.

- **Deployment/runtime wiring**
  - Added `channels`, `channels-redis`, and `daphne` dependencies.
  - Switched Docker web runtime to Daphne ASGI; added Redis service in `docker-compose.yml`.
  - Added phone/OpenLine env vars in `.env.example`.

## Known gaps / not yet validated

- Phase 0 real OpenLine server contract validation (webhook payloads, stream handshake, transfer behavior, latency) is still pending.
- Per-call WS stream-token auth is implemented in the bridge and attach/outbound paths, but real OpenLine custom-parameter/query-string delivery and end-to-end stream behavior still need Phase 0 validation.
- Automated fake-media/bridge tests exist, but real OpenLine device/server end-to-end validation is still pending.
- STT/TTS currently depends on server-side OpenAI-compatible speech endpoints; provider tuning and latency validation pending.
- Basic phone metrics/cost telemetry exist (`/ops/` shows p50/p95 turn latency, estimated cost/cost per minute, and end-reason aggregation), but full cost telemetry, error aggregation across longer windows, and richer alerting remain incomplete. Webhook payloads are sanitized/truncated and `openline_prune` is scheduled.
- Outbound call API exists, but real outbound OpenLine validation is still pending. Rollback runbook and automated rollback handler coverage exist; real-call rollback validation is still pending.

## Upgrade notes

- Do not enable phone voice in production until Phase 0 validation and the full gate pass.
- Apply migrations before starting the web process.
