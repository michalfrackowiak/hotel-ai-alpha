## The guest journey

### Book directly at `/book/`

- The page quotes through `search_availability`, so prices, restrictions and
  rate-plan totals match chat and voice.
- The guest picks the standard rate or any applicable named `RatePlan`; each
  option shows its own total and refundability.
- Submitting the form creates the booking through `create_booking(source=web)`
  and confirms it immediately through `confirm_booking()`.
- Availability results on the home page and the room cards link straight to the
  form with the room type, dates and guest count prefilled.

### Passwordless account at `/my-bookings/`

- A guest requests a magic link by email. `GuestLoginToken` stores only a
  SHA-256 hash, the address, an expiry and a `used_at` marker.
- Tokens are single use, expire after `GUEST_LOGIN_MAX_AGE_MINUTES` (30 by
  default) and are rate-limited per email and per IP.
- The request page always returns the same neutral response; an email is only
  sent when the address already has a booking.
- A signed-in guest sees every reservation tied to the address and can open a
  booking without the original confirmation link.

### Self-service and audit

- Change dates, room type or occupancy, and cancel with a reason, through the
  signed link or the API.
- Cancellation fees come from `cancellation_preview()`; the page, API, agent
  tools and write path all read the same rule.
- Every transition is an append-only `BookingEvent` with actor, channel and
  before/after state.

## Transactional email hardening

- Failed confirmation emails retry with exponential backoff:
  `min(EMAIL_RETRY_BASE_SECONDS * 2^(attempts-1), EMAIL_RETRY_MAX_SECONDS)`.
- Each attempt updates `confirmation_email_attempts`,
  `confirmation_email_last_attempt_at` and `confirmation_email_next_retry_at`.
- The scheduler sidecar runs `send_booking_emails` and only picks up bookings
  whose backoff window has passed and that still have attempts left
  (`EMAIL_MAX_ATTEMPTS`, 5 by default).
- SES (including SNS-wrapped notifications) and Postmark bounce, complaint and
  delivery webhooks are normalised in `apps/hotel/email_webhooks.py` and matched
  by booking reference or provider message id.
- `/ops/` shows delivered, failed and bounced/complained counts plus a table of
  problem deliveries with attempts, next retry and last error.

## Accessibility

- The booking form has labelled controls, a labelled rate-plan radiogroup and a
  contact hint wired with `aria-describedby`.
- The voice page announces call status through a `role="status"` live region,
  names the call button from its visible text (so "Start call" / "End call"
  stay correct) and hides the decorative avatar from assistive technology.
- Both pages keep one `<h1>`, a `<main>` landmark, a skip link and a sane
  heading order.
- `tests/test_accessibility.py` parses the rendered HTML in English and Polish
  and fails on duplicate ids, missing labels, unnamed buttons or links, positive
  tabindex and focusable content under `aria-hidden`. It runs in the normal
  Python CI job.
- A manual axe-core run over the booking page (start and quote states) and the
  voice page in both languages reports **0 violations and 0 incomplete items**.

## Upgrade notes

1. Run `manage.py migrate`. Migrations through `0010_booking_email_retry_fields`
   are required.
2. New optional environment variables: `EMAIL_MAX_ATTEMPTS` (5),
   `EMAIL_RETRY_BASE_SECONDS` (300) and `EMAIL_RETRY_MAX_SECONDS` (21600).
3. The scheduler sidecar now runs `send_booking_emails` in addition to
   `expire_holds` and `reconcile_calendars --apply`; on a host without Docker
   add it to the same cron schedule.
4. No API contract changes. Webhooks remain under
   `/api/v1/email/webhooks/<provider>/`.

## Known limits

- The automated accessibility gate is structural. Colour contrast and the live
  microphone interaction still need a manual review; axe-core was run locally
  with layout-dependent rules disabled.
- Backoff is per booking, not a shared queue; a very large backlog is processed
  serially by the scheduler command.
- SES attachments are still dropped by the v1 SendEmail path; the confirmation
  `.ics` therefore requires SMTP or Postmark.
- The channel manager, multi-currency display and PWA prompt move to v0.6.0.
